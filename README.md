# 신내림 — 신을 부르는 여덟 갈림길

학교의 전시 기획안 발표를 위한 모바일 이야기형 성격테스트 프로토타입입니다.
HTML, CSS, 바닐라 JavaScript로 제작했으며 설치, 빌드, API 키, 서버 프로그램이 필요 없습니다.
기존 Mental-Percentage-Test처럼 GitHub Pages에 올릴 수 있는 독립적인 새 프로젝트입니다.

## 바로 실행하기

1. ZIP 파일을 먼저 압축 해제합니다.
2. `index.html`을 Chrome, Edge, Safari 등의 최신 브라우저로 엽니다.
3. `나의 신 만나러 가기` → `문을 지나가기`를 누릅니다.

문항과 결과는 로컬 파일로 열어도 작동합니다. 결과 링크 공유는 GitHub Pages 공개 후에 사용하세요. 일부 모바일 브라우저에서는 이미지 저장이 사진첩이 아닌 다운로드 폴더로 들어갑니다.

## GitHub에 올리기

기존 멘탈 테스트 저장소를 덮어쓰지 않으려면 새 저장소를 만드세요. 예시 이름은 `Sinnaerim-Test`입니다.

1. 새 저장소를 만들고 이 폴더 **안의 파일과 하위 폴더**를 올립니다.
2. 저장소 최상위에 `index.html`이 보여야 합니다. `sinnaerim/index.html`처럼 폴더가 한 단계 더 생기지 않도록 주의하세요.
3. 저장소 **Settings → Pages → Build and deployment**로 이동합니다.
4. Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/(root)**로 지정하고 Save를 누릅니다.
5. 배포가 완료되면 Pages 설정에 표시되는 실제 주소를 엽니다.

계정이 `OjOj717`, 저장소가 `Sinnaerim-Test`라면 일반적인 주소 형식은 `https://ojoj717.github.io/Sinnaerim-Test/`입니다. 이 주소는 예시이며, 현재 배포된 주소가 아닙니다.

[GitHub 공식 Pages 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

QR 코드는 포함하지 않았습니다. 저장소를 공개하고 최종 주소가 확정되면 직접 제작하면 됩니다.

## 파일 구조

```text
index.html          기본 문서, 메타 정보, 전시 소개 팝업
css/
  style.css         색상, 글꼴, 모바일/데스크톱 레이아웃
js/
  data.js           8개 질문, 선택지, 배점, 6신의 결과 문안
  art.js            안내자·장면·신 오브제의 SVG 일러스트
  main.js           화면 전환, 답변 기록, 공유, PNG 저장
assets/
  favicon.svg       브라우저 탭 아이콘
tests/

.nojekyll           GitHub Pages 정적 파일 배포용

README.md
```

## 구현한 경험

- 버추얼 무당이 프롤로그, 질문, 선택 후 반응, 신의 등장을 안내합니다.
- 8개 질문 × 2개 선택지. 각 선택 뒤 짧은 대사를 읽고 다음으로 갑니다.
- 이전 선택 수정, 같은 탭에서 새로고침 후 진행 복원, 처음부터 다시 하기.
- 영등할망·조왕신·성주신·바리공주·강림도령·히든 측신.
- 실제 선택 최대 2개를 근거로 결과를 설명합니다.
- 결과 미리보기 6종. 미리보기와 실제 결과를 명확히 표시합니다.
- 결과 카드 PNG 다운로드. 지원 브라우저의 기본 공유 메뉴 또는 링크 복사.
- 큰 터치 버튼, 키보드 포커스, 동작 줄이기 설정 대응.
- 외부 글꼴·이미지·라이브러리 요청 없이 실행합니다.

## 무엇을 수정하면 되나요?

**문항/대사/배점:** `js/data.js`의 `questions`를 수정합니다.

- `story`: 상황 설명
- `prompt`: 버추얼 무당의 질문
- `choices[].text`: 선택지
- `choices[].reply`: 선택 후 대사
- `choices[].scores`: 신별 배점
- `choices[].evidence`: 결과에 나올 실제 선택 근거

**결과:** `js/data.js`의 `gods`를 수정합니다.

- `name`, `type`, `tags`: 신 이름, 성격 유형, 태그
- `intro`, `strength`, `care`: 해석 문구
- `oracle`: 신탁 (`\n`은 줄바꿈)
- `mission`: 오늘의 작은 실천
- `lore`, `source`: 원래 전승 설명과 출처

**디자인:** `css/style.css` 맨 위의 `:root`에서 기본 색·글꼴을 바꿀 수 있습니다. 결과별 색상은 `data.js`의 `color`를 수정합니다.

**그림:** `js/art.js`의 SVG는 교체하기 쉬운 프로토타입용 선화입니다. 실물 유물이나 전통 도상을 그대로 재현한 이미지가 아닙니다.

**공유:** 배포 주소를 하드코딩하지 않고 현재 URL을 사용합니다. 저장소 이름이 바뀌어도 상대 경로로 작동합니다. 공유받은 결과는 `#god=E` 같은 미리보기이며, 원래 참여자의 세부 답변을 공개하지 않습니다.

## 점수 규칙 v1

코드: E=영등, J=조왕, S=성주, B=바리, K=강림, H=측신.

- Q1~Q5: 행동 선택에 해당 신 +2.
- Q6~Q8: 각 선택에 연결된 신들 각각 +1.
- 일반 5신의 최고 가능 점수는 모두 7점.
- 동점이면 Q5부터 Q1까지 거꾸로 읽어 동점 신 중 가장 최근에 직접 선택한 신을 판정합니다.
- Q2 B + Q4 B + Q6 A + Q8 B를 모두 고르면 측신이 우선합니다. 무작위 추첨은 없습니다.

256개 응답 조합의 결과: 영등 44, 조왕 51, 성주 30, 바리 68, 강림 47, 측신 16.
이는 실제 관객의 출현 비율이 아닙니다. 실제 분포와 결과의 납득도는 사용자 테스트로 확인해야 합니다. 문항이나 배점을 바꾸면 테스트의 기대값도 검토해야 합니다.

Node.js가 설치되어 있다면 선택적으로 다음 검증을 실행할 수 있습니다.

```bash
node tests/scoring.cjs
```

## 발표 시 설명할 점

- 원안의 청신 복도를 ‘화면에서 고르는 갈림길’로 번안했습니다.
- 버추얼 무당은 이름 없는 내레이션 대신 화면 속 가상 안내자로 유지했습니다. 실제 전승자의 녹음은 포함하지 않았습니다.
- 성격 유형·신탁·오방 배치·히든 조건은 전시용 창작입니다. 심리 진단이나 실제 굿을 제공하지 않습니다.
- 현재는 개인 체험 프로토타입입니다. 관객별 응답 집계, 단체 통계, 계정, NFC, AR, 실제 전시장 연동은 구현하지 않았습니다.
- 이름·연락처를 받지 않고 답변을 별도 서버로 보내지 않습니다. 브라우저 탭의 sessionStorage에 진행을 임시 저장합니다. 전시 소개 팝업에서 지울 수 있습니다.
- 입구의 고민 키워드 선택은 첫 프로토타입에서는 생략했습니다. 현재 신탁은 결과 신에 따라 달라지며 고민별 개인화는 포함하지 않습니다.

## 확인한 범위

- 모든 256개 응답 조합, 여섯 결과 도달, 히든 조건, 답변 근거 검증.
- 브라우저에서 일반 결과와 측신 결과까지 실제 클릭 진행.
- 선택 수정, 결과 새로고침 복원, PNG 다운로드 확인.
- 모바일 크기 화면 검토. 실제 iPhone/Android 기기 및 카카오톡 인앱 브라우저에서는 발표 전 최종 확인이 필요합니다.
